
HTTP/3
- runs over QUIC instead of TCP
- QUIC runs over UDP

QUIC handles reliability/ordering/congestion control itself, in userspace
- not relying on the kernel's tcp stack -> protocol can evolve/deploy faster (no waiting on
  OS updates)

solves tcp's head-of-line blocking
- QUIC streams are independent - a lost packet only blocks the ONE stream it belongs to,
  not every multiplexed stream like http/2-over-tcp does

tls 1.3 is baked in, not a separate layer
- connection setup + crypto handshake combined -> faster to first byte
- 0-RTT resumption possible for repeat connections

connection migration
- quic connections are identified by a connection ID, not the ip:port tuple
- phone switching wifi -> cellular doesn't need to reconnect from scratch

adoption: growing, supported by chrome/firefox, cloudflare, google, etc
no built-in nodejs support for quic/http3 server/client as of this course (would need an
external lib) - test with curl --http3 against a real http/3 site instead
